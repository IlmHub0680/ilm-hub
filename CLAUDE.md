## Stack
- Next.js 14.2.35 (App Router), Prisma 7.10.0 with @prisma/adapter-pg (raw pg driver, NOT the default Prisma engine), PostgreSQL via Prisma Postgres (db.prisma.io).
- Dev machine: Windows, project at `D:\Projects\ilm-hub-production`, also reachable via WSL2 Ubuntu at `/mnt/d/Projects/ilm-hub-production`. Run all `npx prisma migrate dev` / DB-touching commands from a real terminal (WSL2) — the Cowork device-bridge shell has no network path to db.prisma.io (proxy returns 403), so migrations must be run by the user, not by Claude, even though Claude can edit schema.prisma, run `prisma format`/`prisma validate`/`prisma generate` (schema-only, no DB needed).

Fonts: `--font-display` (Lora), `--font-body` (Inter), `--font-mono` (JetBrains Mono), `--font-arabic-display` (Amiri), `--font-arabic` (Noto Sans Arabic) — loaded via Google Fonts `<link>` in `app/layout.jsx`. Reusable `ih-*` classes (`.ih-btn`/`.ih-badge`/`.ih-stat-grid`/`.ih-card`/`.ih-tbl`/`.ih-field`/`.ih-shell`) plus the shared `components/DashboardShell.jsx` (persistent collapsible sidebar; supports both uncontrolled anchor-nav dashboards and controlled tabbed dashboards via optional `onSelect`/`activeId` props) are used across every staff dashboard and admin oversight page. Light theme only — dark mode was explicitly scoped out for this production rollout.

## Architecture: Admin is oversight-only
`/admin` sees real numbers and links **read-only** into every delegated duty's own oversight page (`/admin/<area>`, server components, `requireAdmin`-gated). It never operates a duty directly. Each real duty is owned and operated by its own dashboard, permission-gated by `requireModulePermission(module, "view"|"edit")` from `lib/permissions.ts`. `getStaffDestination(userId)` (also in `lib/permissions.ts`) is the single source of truth for where a logged-in staff member lands after `/staff-login` — it checks role first (SUPER_ADMIN bypass, ADMIN fallback), then walks module `edit` permissions in institutional-hierarchy order, with one position-name-based special case (Academic Advisor, view-only).

## Recurring bug classes to check first (established this project)
1. File save mismatches — verify the actual file on disk before trusting it matches intent, especially after "it's not working."
2. Dynamic route folder naming must exactly match frontend `fetch()` paths — a wrong path is a silent 404, no compile error. Always confirm route files exist at the literal path fetched.
3. Duplicate function declarations are silent (last one wins) — grep-count declarations vs call sites after editing seed/route files.
4. Every redirect/destination target and every `fetch()` target must exist as a real file — cross-check, don't assume.
5. Schema relation back-references — every `@relation(fields:...)` needs its opposite side; run `npx prisma format` + `npx prisma validate` after any schema edit (schema-only, no DB needed, safe to run anytime).
6. Prisma client property names: model "ICTTicket" → `prisma.iCTTicket` (only first letter lowercased).
7. Prisma Postgres P1001 connection errors from a real terminal are usually transient — retry. From the Cowork device-bridge shell they are NOT transient — that shell has no egress to db.prisma.io at all; don't retry there, tell the user to run it themselves.

## Card/shadow standard (important — read before touching admin pages)
Every admin "card" must have a visible shadow, not just a border. The root cause of a recurring "admin looks like flat white boxes" complaint was that `.ih-card`/`.ih-stat-tile`/`.ih-tbl-wrap` in `app/globals.css` used `--shadow-card` (an almost-invisible `0 1px 2px rgba(27,36,31,0.06)`) and `--radius-m` (10px), while the Bookstore admin pages the user holds up as the standard use a much bolder shadow (`0 4px 18px rgba(...,.05-.08)` or stronger) and `--radius-l` (16px). Fixed by switching the shared classes to `--radius-l` + `--shadow-raised` with a hover lift — this alone fixed every page using those classes (the `/admin` hub, Staff, Media Library, and every delegated-duty oversight page). Pages with their own hand-rolled inline card styles (`admin/publishing`, `admin/dashboard/AdminDashboardContent.tsx`, `admin/bookstore/orders`, `admin/admission-fees`, `admin/sponsor-manager`, `admin/bookstore/{categories,assets,submissions}`) needed individual `boxShadow` added to their `var(--surface)` containers; Tailwind-based pages (`admin/analytics`, `admin/newsletter`, `admin/author-approvals`) needed `shadow-sm` bumped to `shadow-lg`. **When adding any new admin card, always give it a real shadow (`var(--shadow-raised)` or an equivalent `0 4px 18px rgba(27,36,31,.08)`-strength shadow) — a border alone reads as a flat box, not a card.**
